## 0. 执行摘要（TL;DR）

研究 4 个本地 e-book 项目：**ReadAny / sageread / omnigram / foliate(-js)**。

**核心结论：没有任何单一项目能覆盖「9 种读书方法 + AI 全流程（读前/读中/读后/复习）」。每个项目各有一块可借鉴的拼图：**

- **foliate-js**（引擎）：成熟 EPUB/PDF 渲染 + CFI 稳定寻址 + `transformTarget`（AI 注入钩子）——**本项目引擎层直接采用**（D1，已确认）。
- **ReadAny**（功能范式）：技能系统 = 「9 种读书方法固化为功能」的现成落地机制；AI provider 三路径；WebDAV 同步——**本项目功能层/同步层主要借鉴源**。
- **sageread**（RAG/Q&A）：向量 RAG + Rust 插件——**Q&A / 强语义检索借鉴源**（只借架构思路，不搬 Rust/AGPL）。
- **omnigram**（仅研究）：AI-native 自托管书库，无间隔重复——**印证「市面阅读器缺『复习』功能」这一市场空白**。

**已确认的关键设计决策（用户拍板）**：
- **D1 引擎**：foliate-js，`vendor-from-main + own patch layer`（非 npm@1.0.1）。
- **D2 AI 设计**：借鉴 ReadAny（provider 抽象 + 技能系统）+ sageread（RAG 向量检索）。omnigram 仅研究。

## 2. 逐项目画像（精简；全文见对应 draft）

### 2.1 ReadAny — AI 阅读助手（**功能范式主要借鉴源**）

- **定位** [MEASURED]：本地优先、开源（MIT）、跨平台（Tauri 桌面 + Expo React Native 移动）的 **AI 阅读助手**，而非传统 PDF/EPUB 阅读器（README_CN.md:3）。
- **架构** [MEASURED]：monorepo，6 个 package——`core`(共享: DB/AI/TTS/sync) / `app`(桌面 Tauri) / `app-expo`(移动, 无 sync) / `server`(独立 Node: AI API + 本地 LLM provider) / `preset-skills`(预置技能, SQL preset) / `foliate-reader`(引擎封装)。
- **三大可借鉴点**：
  1. **技能系统** [MEASURED, docs/skills-design.md]：Skill Bundle（`prompt`/`agent`/`script` 三种 kind）+ **Capability Catalog**（稳定工具 API：`reader.getCurrentBook`/`highlights.listByBook`/`notes.create`…）+ **AI 自然语言创建 skill**（缺信息只问 1-3 问）+ **access 分级**（`none/read/write/full`）+ 脚本运行时 + 同步/导入导出。**这是「9 种读书方法固化为功能」的现成落地范式**（详见 §5）。
  2. **AI provider 三路径** [MEASURED]：内建（本地 SQLite FTS5+LIKE，非向量）/ 外部 API（OpenAI-compatible）/ 本地 LLM（Ollama/LM Studio，经 `server` 代理）。
  3. **WebDAV 同步** [MEASURED, sync/index.ts]：5-step pipeline（collect→fetch→compare→apply+resolve→persist）+ 4 冲突策略 + delta/full。
- **许可** [MEASURED]：MIT（比 sageread 的 AGPL-3.0 **更宽松**，对商业/闭源集成友好）。

### 2.2 sageread — RAG-first AI 阅读器（**Q&A / 强语义检索借鉴源**）[AGPL-3.0]

- **定位** [MEASURED]：AI-first 阅读器，Tauri + React (Vite) + Rust（4 crate：`server`/`ui`/`db`/`plugins`）+ 向量库（sqlite-vec/LanceDB/Qdrant/PG，默认 sqlite-vec）。
- **可借鉴点**：
  1. **RAG 管线** [MEASURED, rag_pipeline.rs:160-238]：chunk 生成（按章节）→ embedding → store → retrieve（向量 + BM25 全文，**RRF 融合**）→ context 组装 → LLM。
  2. **Rust 插件系统** [MEASURED, plugin.rs:52-80]：dlopen `.so`/`.dylib`，`#[sageread::plugin]` macro 导出 `PluginEntry`。
  3. **Q&A** [MEASURED, qa.rs]：双模式（`QAMode`）+ 来源引用（book/chunk/page 定位）。
- **不可直接搬** [INFERRED]：Rust 栈 + AGPL 与本项目的 TS 选型/许可冲突——**只借鉴架构思路（RAG 管线、插件隔离），不搬代码**。

### 2.3 foliate / foliate-js — 成熟 EPUB/PDF 引擎（**本项目引擎基座**）[MIT]

- **foliate** = Web 阅读器（React，支持 EPUB/PDF/MOBI/DOCX/FB2）；**foliate-js** = 引擎核心（TS，无 React 依赖）。**本项目要 vendor 的是 foliate-js**。
- **可借鉴 API surface** [MEASURED]：
  - `createDocument(html, {csp})` / `parseStylesheet(css)`（完整 CSS cascade：specificity/媒体查询/`@supports`）。
  - **`transformTarget(target, transform)`** = **AI 注入的稳定钩子**（DOM 级，非 Cove；transform 返回 `Node`=替换 / `true`=保留 / `false|=null`=删除）。
  - **CFI**（稳定跨版本寻址）+ `textWalker`（全文遍历，`skipHiddenText` 选项）。
- **Gotchas** [MEASURED/INFERRED]：CFI 需 anchor 元素（无 anchor 的 body/p 无法定位）；CSP default `script 'none'`（要跑脚本须改 CSP）；foliate 定制 fork 的 `autoTransform`/`transformSource` **不在** upstream foliate-js，需 own patch。
- **明确不借** [决策]：React view 层、Cove 高亮系统、UI 组件——只借引擎核心。

### 2.4 omnigram — AI-native 自托管书库（**仅研究，不借鉴**）

- **定位** [MEASURED]：AI-first 自托管书库，Flutter（移动/桌面）+ Go 后端。核心理念：**每本书入库即生成 AI 分析**（summary / keyPoints / quotes / Q&A），而非「阅读器 + AI 插件」。
- **关键发现** [MEASURED, grep]：**无间隔重复 / spaced-repetition 机制**（搜 `spaced|review|forgetting curve` 于 backend+frontend 零命中）。
- **AI 分析** [MEASURED]：入库触发 `ProcessBook` → LLM（OpenAI/Anthropic/Ollama 可配置）生成 BookAnalysis；支持手动重分析、单字段重新生成。
- **印证** [INFERRED]：市面 AI 阅读器普遍「重入库分析、轻复习巩固」——**#6 SuperMemo 间隔重复是市场空白点，help-you-read 要补上**。
- **不借鉴** [决策]：用户明示仅研究；其 Go/Flutter 栈与本项目 TS 选型不符。

## 4. 关键设计决策（已确认 + 建议）

- **D1（用户已确认）**：EPUB 引擎 = foliate-js，**vendor-from-main + own patch layer**（非 npm@1.0.1）。理由：npm 版过老（2023-04，CHANGELOG.md:9）；main 有 165 commits of fixes（CHANGELOG.md:8）；ReadAny 已验证「vendored foliate-js + transformTarget」可行（EPUB_CONVERSION_PLAN.md）。
- **D2（用户已确认）**：AI 设计借鉴 = ReadAny（provider 抽象 + 技能系统）+ sageread（RAG 向量检索）。omnigram 仅研究。
- **D3（建议）**：数据模型 = 本地优先 SQLite，实体参考 ReadAny（books/highlights/notes/tags/messages/skills）+ 按需加向量 chunks（承载 #6/#8 强语义检索）。[待 P6 定 schema]
- **D4（建议）**：跨设备同步 = WebDAV 快照（借 ReadAny 5-step pipeline），但引入**向量时钟 / per-row Lamport counter**解决「相同 updatedAt 冲突需 manual」硬弱点。
- **D5（建议，核心）**：**9 种读书方法 → 9 个预置 Skill**（借 ReadAny 技能系统范式），按读前/读中/读后/复习组织；access level（none/read/write/full）= AI 介入边界。

## 5. 对 help-you-read 的设计启示（「把 9 种方法固化为功能，AI 全流程介入」）

**建议核心架构**：
```
foliate-js（引擎: 渲染 + CFI + transformTarget）   [D1]
  + AI provider 抽象（本地LLM/外部API, 借 ReadAny; RAG向量检索, 借 sageread）  [D2]
  + Skill 系统（9种读书方法→9个预置Skill, 借 ReadAny; 读前/读中/读后/复习分类）  [D5]
  + SQLite 数据层（books/highlights/notes/messages/skills/reviews, 本地优先）  [D3]
  + WebDAV 同步（跨设备, 借 ReadAny + 向量时钟改进）  [D4]
```

**9 种方法 → 功能映射（初版，待 P5 brainstorming 细化）**：

| # | 方法 | 阶段 | 功能形态（Skill kind） | AI 介入点 |
|---|---|---|---|---|
| 1 | RIA 便签 | 读中+复习 | script/agent：选中→I/A1/A2 三栏便签，A2 贴墙 | AI 辅助生成 A（关联）|
| 2 | 四层次阅读(Adler) | 读前+读中 | agent：定义问题→快速定位→主动阅读 4 问 | AI 生成「快速定位报告」+「4 问」|
| 3 | 三遍阅读(Paul Graham) | 读前/中/后 | agent：三遍递进（略读→细读→笔记转化）| AI 生成每遍摘要/批判 |
| 4 | 宝塔式(邹韬奋) | 读前+读中 | agent：选书→由广入深分层 | AI 推荐「塔尖/塔身/塔基」书单 |
| 5 | 麦肯锡高效(赤羽雄二) | 读前+读中+复习 | agent：15min 判断→集中 3-7 天→数据库输出 | AI 生成「值不值得读」+ 讨论问题 |
| 6 | SuperMemo 间隔重复 | **复习** | script：卡片 + 遗忘曲线（EF/SM-2）调度 | AI 从划线/笔记生成卡片 |
| 7 | 名人读书法 | 读前+读中 | prompt/agent：按名人风格（毛泽东批注/朱熹三到/爱因斯坦总-析）| AI 按风格生成批注 |
| 8 | 芒格多元思维 | 读后+复习 | agent：逆向拆解（反过来想）+ 跨学科模型映射 | AI 生成「逆向视角」+ 多元模型应用 |
| 9 | 共振阅读(渡边康弘) | 读前+读中 | agent：斜读/跳读/手指辅助→找有用内容 | AI 生成「共振点」（与既有知识连接）|

**AI 介入的四个阶段（= Skill 分类维度）**：
- **读前**：快速定位报告(2) / 值不值得读(5) / 书单推荐(4) / 总览(7-爱因斯坦)
- **读中**：辅助批注(1,7) / 主动阅读 4 问(2) / 三遍细读(3) / 共振点(9)
- **读后**：笔记转化(3.3) / A2 贴墙(1) / 逆向拆解(8)
- **复习**：间隔重复卡片(6) / 讨论问题(5.3) / 持续迭代(8.3)

> **设计原则**：阶段（读前/中/后/复习）= Skill 的**分类维度**；方法 = 具体的 **Skill**（kind=prompt/agent/script + access level）。AI 在每阶段按用户启用的 Skill 自动介入。
