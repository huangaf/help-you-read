# 四个本地电子书项目：持久数据模型对比

> 目的：为 **help-you-read**（local-first、AI 全流程介入的 AI 阅读器）设计数据模型，先摸清四个参照项目各自**持久化了什么**。
> 本文只覆盖「持久数据」：落到磁盘/数据库的实体、表、文件，其关键字段与相互关系。
> 每条论断标注 **MEASURED**（我实际读了该 schema/DDL/模型文件）或 **INFERRED**（依据代码结构/注释推断，未逐字段核实）。
> 所有 file:line 引用均为**相对各项目仓库根目录**的路径。

---

## 0. 一句话概览（先看这个）

| 项目 | 定位 | 持久化范式（架构立场） |
|---|---|---|
| **SageRead** | Tauri + React，单用户本地 AI 阅读器 | **纯本地 SQLite，单库**；用 JSON-blob 反范式化复杂数据；无同步 |
| **ReadAny** | TS monorepo，local-first 且支持跨设备同步 | **SQLite 双库**：`readany.db`(可同步) + `readany_local.db`(向量/本地专用)；全规范化 + 完整同步引擎 |
| **Omnigram** | Go(GORM)+Flutter，自托管多用户服务器 | **PostgreSQL(+pgvector) + BadgerDB 双层**；服务器为真源、客户端 sqflite 镜像；多用户 |
| **foliate-js** | EPUB/MOBI/FB2/PDF 渲染引擎库 | **无持久数据模型**；仅内存态，持久化交由宿主 App 完成 |

> 关键洞察：**四个项目对「AI 产物怎么存」的答案各不相同**——SageRead 把它塞进 JSON-blob，ReadAny 拆成规范化表 + 独立本地库，Omnigram 用一张多态 `ai_result` 表 + pgvector。这正是 help-you-read 需要自己做出选择的地方（见 §5）。

## 2. SageRead（Tauri + React，纯本地单用户）

**存储引擎 [MEASURED]**：SQLite（`sqlx::Sqlite/SqlitePool`）。DB 文件为 `{app_data_dir}/database/app.db`；首次运行执行内嵌 `schema.sql` 建表，并从 `default-skills.json` 播种系统技能。
> 引用：`packages/app/src-tauri/src/core/database.rs:15-49`；`.../core/schema.sql`（全文 143 行）
> **纯本地、单用户、无同步**（schema.sql 无任何 sync 列/墓碑）[MEASURED]

**8 张表 [MEASURED: schema.sql]**：
1. **`threads`**（行 1-10）：id(PK)、book_id(FK→books, CASCADE)、`metadata`(JSON)、title、**`messages`(TEXT，整段 AI 对话序列存成 JSON-blob)**、created_at/updated_at。
   → **设计特征**：AI 对话不拆表，整段序列化进一列。简单但难做增量同步/单条检索。
2. **`books`**（行 12-27）：id、title、author、format、file_path、cover_path、file_size、language、`tags`(JSON text)、created_at/updated_at。
   → **无** group_id、rating/reviews、soft-delete(deleted_at)、vector 列（对比 ReadAny 缺这些）。
3. **`book_status`**（行 29-42）：book_id(**PK，1:1**)、status(unread/reading/completed)、progress_current、progress_total、location(CFI)、last_read_at、started_at、completed_at、`metadata`(JSON，存设置/偏好)。
   → **设计特征**：把「阅读进度」从 books 拆成独立表（对比 ReadAny 用 books.progress 列）。
4. **`reading_sessions`**（行 45-54）：id、book_id(FK CASCADE)、started_at、ended_at、duration_seconds、created_at/updated_at。
   → 比 ReadAny 的会话表**字段更简**（无 pages_read/characters_read/state）。
5. **`tags`**（行 76-82）：id、name(UNIQUE)、color、created_at/updated_at。
   → **无 `book_tags` 连接表**：标签以 JSON 形式反范式化存在 books.tags / notes.tags（对比 ReadAny/Omnigram 有独立 junction 表）。
6. **`notes`**（行 88-97）：id、book_id(**FK→books, SET NULL，可空**=允许独立笔记)、`book_meta`(JSON 存 title/author)、title、content(支持 Markdown)。
   → **RIA 便签的落点**：`book_id` 可空意味着笔记能脱离具体书存在（跨书/自由卡片）。
7. **`book_notes`**（行 105-121）：id、book_id(FK CASCADE)、**type**(bookmark|annotation|excerpt)、**cfi**、text(选中原文)、style(highlight|underline|squiggly)、color、note、**context_before(前文上下文)**、**context_after(后文上下文)**。
   → **★ 四项目中唯一显式存「选中文本 + 前后上下文」的项目**。这正是 AI 辅助阅读（RIA/麦肯锡）能离线拿到真实文本依据的关键。
8. **`skills`**（行 130-138）：id、name(UNIQUE)、content(Markdown SOP)、is_active、**is_system**(1=系统技能不可删)、created_at/updated_at。

**关系**：threads.book_id→books(CASCADE)；book_status.book_id→books(1:1)；reading_sessions.book_id→books(1:N)；notes.book_id→books(**SET NULL**, 可空)；book_notes.book_id→books(CASCADE, 1:N)。skills/tags 独立。

**设计签名（help-you-read 可借鉴/规避）**：
- JSON-blob 反范式化（threads.messages、books.tags、notes.book_meta、book_status.metadata）→ 本地单机简单，但**不利于跨设备同步与单条查询**。
- `book_notes` 的 **context_before/after + type/style/color** → 强烈建议 help-you-read 采纳（见 §5.3）。

## 3. ReadAny（TS monorepo，local-first + 跨设备同步）

**存储引擎 [MEASURED]**：SQLite（WAL journal_mode、synchronous=NORMAL、foreign_keys ON、busy_timeout 15000）。**双库架构**：
- `readany.db`（主库，可跨设备同步）[db-core.ts:17, 130]
- `readany_local.db`（本地专用，存向量/嵌入，**不参与同步**）[db-core.ts:18, 152]
> **★ 核心设计决策**：把「重且模型相关、不宜同步」的向量嵌入与「轻且需跨设备一致」的用户数据**物理隔离到两个库**。

**主库实体 [MEASURED: db-core.ts initDatabase + migrations.ts]**：
1. **`books`**（db-core 行 337-364 + migrations）：id、file_path、format(默认 epub)、title、author、publisher、language、isbn、description、cover_url、publish_date、rating(REAL)、reviews、subjects(JSON)、total_pages、total_chapters、**group_id**(FK→book_groups)、added_at、last_opened_at、**deleted_at(软删除)**、progress(REAL)、current_cfi、is_vectorized、vectorize_progress、tags(JSON '[]')；同步列：updated_at、**file_hash**、**sync_status**(local/remote/downloading)、**sync_version**、**last_modified_by**。
2. **`book_groups`**（行 368-376）：id、name、sort_order、created_at/updated_at、sync_version、last_modified_by。
3. **`highlights`**（行 380-391）：id、book_id(FK CASCADE)、cfi、text、color(默认 yellow)、note、chapter_title、created_at/updated_at。
4. **`notes`**（行 395-407）：id、book_id(FK CASCADE)、**highlight_id**(笔记可挂到高亮上)、cfi、title、content、chapter_title、tags(JSON)、created_at/updated_at。
5. **`bookmarks`**（行 411-419）：id、book_id(FK CASCADE)、cfi、label、chapter_title、created_at(+updated_at)。
6. **`tags`**（行 423-427）：id、name(UNIQUE)、updated_at。
7. **`book_tags`**（行 431-439）：id、book_id(FK)、tag_id(FK)、updated_at、**UNIQUE(book_id, tag_id)**（规范化连接表，对比 SageRead 的 JSON）。
8. **`threads`**（行 443-451）：id、book_id(可空)、title、**memory_summary**(滚动记忆)、memory_updated_at、memory_message_count、created_at/updated_at。
   → **★ 滚动记忆**：长对话用「摘要 + 计数」压缩上下文，控制 token。
9. **`messages`**（行 456-465）：id、thread_id(FK CASCADE)、role、content、**citations(JSON)**、**tool_calls(JSON)**、reasoning、created_at(+parts_order)。
   → **★ 规范化消息表**（对比 SageRead 的 JSON-blob），带引用/工具调用/推理，AI 可观测性强。
10. **`skills`**（行 470-481）：id、name、description、icon、enabled、parameters(JSON '[]')、prompt、**built_in**、created_at/updated_at。
11. **`reading_sessions`**（行 485-496）：id、book_id(FK CASCADE)、started_at、ended_at、**total_active_time**、**pages_read**、**characters_read**、state(默认 active)、updated_at。
    → **字段最全的会话表**（对比 SageRead/Omnigram）。
12. **`feedback`**（migrations 行 90-108）：id、issue_number、issue_url、title、type(默认 other)、status(默认 open)、created_at/updated_at、has_new_reply、comment_count。（应用反馈，非阅读数据）
13. **`sync_tombstones`**（db-core 行 564-572）：id+table_name(复合主键)、deleted_at、device_id。（删除墓碑，跨设备同步）
14. **`sync_metadata`**（db-core 行 578-583）：key(PK)、value。（存 device_id、迁移标志等）
15. **`schema_migrations`**（migrations 行 134-140）：version(PK)、description、applied_at。（迁移版本表）

**本地库（不同步）实体 [MEASURED: db-core.ts initLocalDatabase]**：
16. **`chunks`**（行 752-763）：id、book_id、chapter_index、chapter_title、content、token_count、start_cfi、end_cfi、segment_cfis、**embedding(BLOB, float32)**、updated_at。
17. **`vector_index_provenance`**（行 770-777）：book_id(PK)、model_kind、**model_id**、endpoint、dimensions、created_at。
    → **★ 嵌入的「出处」记录**：换模型/端点即可判定旧向量作废，无需重算。

**关系**：highlights/notes/bookmarks/reading_sessions.book_id→books(CASCADE)；notes.highlight_id→highlights(笔记可挂高亮)；books.group_id→book_groups；threads.book_id(可空)、messages.thread_id→threads(CASCADE)；book_tags 连接 (book_id, tag_id)。

**设计签名（help-you-read 最值得抄的作业）**：
- **双库物理隔离**（同步数据 vs 本地向量）→ local-first 的正解。
- **完整同步引擎**（墓碑 + sync_version + last_modified_by + device_id）→ 跨设备一致。
- **软删除**（books.deleted_at）+ 孤儿清理（cleanupOrphanedSyncRows）。
- **threads.memory_summary** 滚动记忆 + messages 携带 citations/tool_calls/reasoning/parts_order。

## 4. Omnigram（Go/GORM + Flutter，自托管多用户服务器）

**存储引擎 [MEASURED]**：**双层**。
- SQL 层：GORM。`DSN()` 代码路径**仅实现 postgres + mysql**（`orm.go:88-97` 的 switch 无 sqlite 分支）。
  → **默认部署**：`DB_DRIVER: postgres`，镜像 `pgvector/pgvector:pg17`（PostgreSQL + **pgvector** 向量扩展）[docker-compose.yml:12-35, 29]。
  → **因此**：README 宣称的「SQLite/PostgreSQL/MySQL」中，SQLite 为 **INFERRED/未在我所读文件里实现**（默认与受测路径是 Postgres+pgvector）。
- KV 层：**BadgerDB**（`bucket/key → bytes` 的对象存储，Put/Get/Batch/Upload）[badgerdb.go]。
  → KV 存的是**二进制产物**（封面图、TTS 音频等）[INFERRED：未读填充 KV 的 service 层]。
- **客户端**（Flutter）用 sqflite **镜像服务器数据以支持离线**[MEASURED: ai_result.go:4、companion.go:5 代码注释]。

**GORM 实体（`server/schema/*.go`）**：
1. **`Book`**（book.go:79-123）：id(char24 PK)、size、path(不返回前端)、ctime/utime、title、sub_title、language、cover_url、uuid、isbn、asin、**identifier(唯一索引)**、category、author/author_url/author_sort、publisher/description、file_type(EPUB/AZW3/MOBI/PDF/TXT/MD/FB2)、series/series_index、publish_date、rating(float32)、**tags**(`Tags`=[]string，逗号拼接或 PG jsonb)、publisher_url、count_visit/count_download。
   → **进度不在此表**（在独立 ReadProgress）。identifier 用 MD5(所有 identifier) 做去重键。
2. **`Annotation`**（annotation.go:11-25）：id(autoInc PK)、user_id、book_id、device_id、chapter、content、**selected_text**、cfi、page_number、position、color、**type**(note|highlight|bookmark)、ctime/utime。
   → **一张表 + type 判别**（对比 SageRead 两张表、ReadAny 三张表）。
3. **`Session`**（session.go:11-26）：session(char36 PK)、refresh_token、user_id、remote_ip(cidr)、user_agent、device_id/device_model/device_type、district_id、from_url、duration、ctime/utime。（**认证会话**，非阅读会话）
4. **`ReadProgress`**（read_process.go:12-28）：id(PK)、book_id、user_id[唯一索引对]、start_date、updated_at、**expt_end_date**(默认按 15 天预估)、end_date、progress_index(章节定位)、progress(float32 %)、para_position。
   → **每 user+book 一条**（多用户下的进度）。
5. **`ConceptTag`**（concept.go:9-21，表名 concept_tags）：id、user_id、book_id、name(200)、**source**(text，来源=高亮/笔记原文)、note_id、ctime。
6. **`ConceptEdge`**（concept.go:24-36，表名 concept_edges）：id、user_id、**source_id**、**target_id**、weight(float64 默认 1.0)、**reason**(text，AI 生成的关联原因)、ctime。
   → **★ 跨书知识网络**：ConceptTag=节点(概念)，ConceptEdge=边(跨书关联，带权重与 AI 理由)。四项目中**唯一**显式建模知识图谱。
7. **`CompanionChat`**（companion.go:5-14）：id(autoInc PK)、user_id、book_id、role(user|companion|system)、content(text)、chapter、cfi、ctime。
   → AI 伴读对话；**服务器为真源，客户端 sqflite 镜像**。
8. **`MarginNote`**（companion.go:17-32）：id、user_id、book_id、chapter、cfi、content、**related_book_id**、related_book_title、related_highlight、**confidence**(float64 0.5)、dismissed(bool)、helpful(bool)、ctime/utime。
   → **★ 跨书「边注」**：把当前书某处与**另一本书**的关联写进页边，带置信度与 helpful/dismissed 反馈。直接对应「共振阅读」。
9. **`Tag`/`BookTagShip`**（tag.go:9-50）：`Tags`=[]string；`BookTagShip{ id, book_id, tag }`（连接表）。
10. **`FavBook`**（favorite_book.go:8-14）：id、book_id、user_id[唯一索引对]、created_at/updated_at。（收藏）
11. **`AiResult`**（ai_result.go:5-13）：id(autoInc PK)、user_id、book_id、**result_type**(contextBar|summary|autoTag|glossary|narrative…)、**cache_key**(500，复合键对齐客户端缓存)、content(text)、ctime/utime。
    → **★ 多态 AI 产物**：一张表 + result_type 判别 + cache_key 幂等键，统一承载所有 AI 功能（对比 SageRead 只存 skills、无独立产物表）。

**未逐字段核实（仅确认存在）[INFERRED]**：`user.go`(多用户模型)、`api_key.go`、`audiobook.go`、`tts.go`、`book_epub.go`、`companion_profile.go`（AI 人格 TARS）。

**关系**：Annotation/ReadProgress/FavBook/CompanionChat/MarginNote/AiResult 均带 **user_id + book_id**（多用户、按书）；ConceptEdge.source_id/target_id→ConceptTag.id（知识图边）；ConceptTag.note_id→annotation(概念源自某笔记/高亮)；Session.user_id→users。

**设计签名（help-you-read 可借鉴/规避）**：
- **多用户**（每实体带 user_id）——help-you-read 若只做单用户本地，可省去这一维。
- **多态 `AiResult`（result_type + cache_key）** → 承载多种 AI 产物的优雅范式。
- **知识图谱（ConceptTag+ConceptEdge）** + **MarginNote 跨书边注** → AI 阅读器最有辨识度的能力。
- **服务器为真源 / 客户端镜像**——与 help-you-read 的 **local-first 立场相反**（help-you-read 应以本地为真源）。
- **双层存储（SQL + BadgerDB KV）** → 结构化数据与二进制产物分离。

## 5. 对 help-you-read 的设计启示（local-first AI 阅读器）

> 目标：**把 9 种读书方法固化为软件功能，AI 在「读前/读中/读后/复习」全流程自动介入**，且 **local-first**。
> 以下 5 条均为「从参照项目里可直接抄的作业」，并标注其来源。

**① Local-first 双库架构（抄 ReadAny）**
把持久化物理拆成两层：(a) **可同步的"轻"用户数据**（books、annotations/notes/bookmarks、AI 对话 threads/messages、reading_sessions、skills）与 (b) **本地专用的"重"数据**（向量嵌入/chunks、各方法的产物缓存）。
- 默认一切落本地，守住 local-first；跨设备同步做成**可选开关**。
- 同步引擎抄 ReadAny：`墓碑 sync_tombstones + sync_version(单调递增) + last_modified_by + device_id`。
- **向量/模型产物永远本地**：换模型或端点即整体作废（ReadAny `vector_index_provenance` 记录 model_id/dimensions 正是为此——避免跨设备同步到"错模型"的脏向量）。
> 来源：ReadAny `db-core.ts:17-18, 564-583`。与 Omnigram「服务器为真源」立场**相反**——help-you-read 必须以**本地为真源**。

**② 九种方法 → 一张多态 `method_artifact` 表（抄 Omnigram AiResult）**
用**单表 + `method` 判别列**(ria_note | four_level | three_pass | tower | mckinsey | supermemo | celebrity | munger | resonance) + `idempotency_key`，统一承载九种方法产出的"AI 生成结构化内容"。
- 理由：九法产物共享同一生命周期（**生成 → 缓存/幂等 → 审阅 → helpful/dismissed 反馈**），拆成 9 张表只会造成 schema 膨胀与维护地狱。
- **例外**：**SuperMemo 间隔重复单独建表**。它有本质不同的**时间/调度形态**（due_date、interval、ease_factor、lapses/retrieval_count），塞进多态表会污染 schema，也破坏其「到期即弹复习」的查询路径。
> 来源：Omnigram `ai_result.go:5-13`（result_type + cache_key 多态范式）。

**③ 标注即存"上下文"（抄 SageRead book_notes）**
每条高亮/笔记持久化 **选中文本 + context_before(前文) / context_after(后文) + CFI 定位**。
- 这是 AI 辅助 **RIA / 麦肯锡**能在**离线**拿到真实文本依据的前提——用户断网时 AI 仍能基于已落库的上下文作答，而不是只拿到一句孤立高亮。
- 四项目中**仅 SageRead** 显式做这件事 → help-you-read 应把它当**一等需求**（非可选字段）。
> 来源：SageRead `schema.sql:105-121`（context_before/context_after + type/style/color）。

**④ 显式跨书知识图谱（抄 Omnigram ConceptTag/ConceptEdge + MarginNote）**
持久化两类数据：(a) **概念节点** `ConceptTag`（user+book+name+source+note_id，从笔记/高亮自动抽取）；(b) **跨书概念关系** `ConceptEdge`（source_id/target_id/weight/reason-AI生成的关联理由）。
- 作用：把散落各书的碎片高亮，沉淀成**可查询、可推理的"知识网络"**。
- 直接支撑 **共振阅读**（跨书同概念互证）与 **芒格多元思维**（跨领域模型互联）。
- 四项目中**仅 Omnigram** 有此能力 → 是 AI 阅读器**最大差异化**，help-you-read 应尽早纳入。
> 来源：Omnigram `concept.go:9-36` + `companion.go:17-32`(MarginNote 跨书边注)。

**⑤ 进度与会话分离 + 软删除（抄 ReadAny/Omnigram）**
同时持久化：(a) **每书累计进度**（status、progress%、location/CFI）；(b) **离散 `reading_sessions`**（started_at/ended_at/duration、pages_read、characters_read）。
- 会话级**时间序列**是 **复习调度（SuperMemo）**与**阅读习惯分析/Insights** 的数据基础——只存一个进度标量，无法回答"我这一周每天读了多久、哪本书读得最投入"。
- 若跨设备同步在路线图上：补 **soft-delete（books.deleted_at）+ 墓碑 + 孤儿清理**。
> 来源：ReadAny `db-core.ts:485-496, 358, 564-572`；Omnigram `read_process.go:12-28`。

## 附录：9 种读书方法 → 数据模型映射

> 「phase」= 读前/读中/读后/复习。「持久化建议」= help-you-read 应落库的实体。
> 「参照」= 哪个参照项目的哪张表最接近该方法的持久化形态。

| # | 方法 | phase | 持久化建议（help-you-read） | 最近参照（项目.表/字段） |
|---|---|---|---|---|
| 1 | **RIA 便签**（R-重读 I-述评 A-应用） | 读中+读后 | `method_artifact(method='ria_note')`：存 R(原文/CFI)、I(复述)、A(应用) 三段 + **context_before/after** | SageRead `book_notes`(选中文本+前后文)；ReadAny `notes.highlight_id` |
| 2 | **四层次阅读**（字词/观点/评论） | 读前+读后 | `method_artifact(method='four_level')`：分三层结构化字段(如 JSON)存逐层产出 | Omnigram `AiResult`(多态 result_type + 结构化 content) |
| 3 | **三遍阅读**（速览/细读/内化） | 读中+读后 | `method_artifact(method='three_pass')`：三遍各一条记录，关联 progress 阶段 | Omnigram `AiResult`(多态) + `ReadProgress.progress_index` |
| 4 | **宝塔式**（逐层抽象/金字塔） | 读后 | `method_artifact(method='tower')`：**嵌套/层级**结构（父摘要→子论点），可用 JSON 树或自引用 | Omnigram `AiResult`(多态)；层级建议 JSON 树（local-first，免建自引用表） |
| 5 | **麦肯锡高效**（结论先行/金字塔原理） | 读中+读后 | `method_artifact(method='mckinsey')`：结论 + 支撑要点(结构化) + **context** | SageRead `book_notes`(上下文)；Omnigram `AiResult` |
| 6 | **SuperMemo 间隔重复**（SM-2） | 复习 | **独立表 `review_items`**：card_id、book_id、due_date、interval_days、ease_factor、lapses、last_reviewed_at、content | 四项目**均无**此表 → help-you-read **需自建**（形态与其余 8 法不同） |
| 7 | **名人读书法**（以某大师视角读） | 读前+读中 | `method_artifact(method='celebrity')`：persona(名人) + 视角化产出；persona 可复用为配置 | Omnigram `CompanionChat`(role=user/companion/system) + `companion_profile`[INFERRED] |
| 8 | **芒格多元思维**（跨学科模型） | 读后+复习 | `ConceptTag`(节点) + `ConceptEdge`(跨书/跨领域边, weight+reason) | Omnigram `concept.go:9-36`（知识图谱） |
| 9 | **共振阅读**（多书同主题互证） | 读后+复习 | `MarginNote`(跨书边注: related_book_id + confidence) + 复用 `ConceptEdge` | Omnigram `companion.go:17-32`(MarginNote) + `concept.go` |

**Phase 覆盖小结**：
- **读前**：方法②⑦（建立框架/视角）→ 落 `method_artifact`，并预生成 books 元数据(cover/summary/autoTag，参照 Omnigram `AiResult result_type=summary/autoTag`)。
- **读中**：方法①③⑤⑦（伴随式介入）→ 标注即存上下文(③) + `CompanionChat` 伴读。
- **读后**：方法①②③④⑤⑧⑨（沉淀/内化）→ `method_artifact` + 知识图谱(⑧) + 跨书边注(⑨)。
- **复习**：方法⑥（SM-2 调度）+ ⑧⑨（跨书巩固）→ `review_items` + 会话时间序列(⑤)。

> **结论**：9 法中，8 法可收敛进**一张多态 `method_artifact` 表**（+ 知识图谱/边注两张辅助表）；仅 **SuperMemo(⑥) 需独立建表**。配合 local-first 双库与「标注即存上下文」，即可用**至多 6~7 张表**承载全部功能，避免 schema 膨胀。
