# AI 辅助阅读器 · 初步方案

> 本文档记录基于《读书方法总结》规划开发的 AI 辅助阅读器初步方案（已获用户确认）。
>
> 创建日期：2026-09-01
> 状态：已确认，进入详细设计阶段

---

## 1. 产品定位

**方法论驱动的 AI 阅读工作台**——把 9 种读书方法全部固化为软件功能，AI 在"读前 / 读中 / 读后 / 复习"全流程自动介入。

与现有产品（ReadAny、SageRead、Omnigram 等）的差异：现有产品几乎都是"RAG 对话 + 语义搜索 + 高亮笔记"通用配方，缺少方法论驱动。本产品把读书方法固化为可执行的阅读流程，AI 在流程每个环节自动介入。

## 3. 9 种方法 → 功能模块映射（全部纳入 MVP，分批实现）

| 读书方法 | 功能模块 | 落地形态 |
|---------|---------|---------|
| **四层次阅读** | 检视阅读报告 + 分析阅读问答 + 主题阅读 | 读前 AI 生成结构图/核心论点；读中 RAG 深度问答；读后跨书检索 |
| **三遍阅读法** | 三遍阅读模式 | 模式一纵览（AI 梗概）→ 模式二细节（AI 解释）→ 模式三笔记（AI 整理成文） |
| **RIA 便签法** | RIA 便签生成 | 选中段落 → AI 生成 I/A1/A2 三色便签，可编辑，贴墙（行动看板） |
| **宝塔式读书法** | 分级重读管理 | 阅读分级标记（浏览/精读/最爱），重读清单与频率统计 |
| **麦肯锡精英法** | 读书档案 | 读书目的 → 收获 → 行动计划 → 输出记录，档案可导出 |
| **SuperMemo 间隔重复** | 记忆复习系统 | 高亮/便签转闪卡，间隔重复调度（FSRS 算法），每日复习，可导出 Anki |
| **名人读书法** | 标注系统 | 五色高亮 + 批注 + 圈点（不动笔墨）；跳读模式（鲁迅）；由薄到厚概念展开（华罗庚） |
| **芒格多元思维** | 跨书关联 + 思维模型库 | 跨书概念聚合、知识网络图、思维模型标签 |
| **共振阅读法** | 关键词/目标驱动阅读 | 关键词定位阅读、目标提问式阅读、手指辅助（高亮跟随） |

## 4. 技术架构

```
┌─ Web MVP（Next.js + TypeScript）────────────────────────┐
│  三栏布局：阅读区(foliate-js) │ 标注/便签/档案 │ AI 对话 │
│  + 复习页（间隔重复） + 行动看板（A2 便签墙）            │
└──────────┬─────────────────────────────────────────────┘
           │ 本地优先（SQLite / IndexedDB 持久化）
┌──────────▼─────────────────────────────────────────────┐
│  核心服务层                                              │
│  ├─ 书籍解析：EPUB/PDF/TXT → 章节化文本                  │
│  ├─ 分块索引：800字块（200重叠）+ BM25                    │
│  ├─ 向量库：本地（sqlite-vec）或在线 embedding            │
│  └─ 数据模型：书库/高亮/便签/档案/闪卡/复习调度/阅读统计  │
└──────────┬─────────────────────────────────────────────┘
           │
┌──────────▼─────────────────────────────────────────────┐
│  AI 层：LangChain.js + 多模型（OpenAI/Claude/DeepSeek/Ollama）│
│  ├─ RAG 混合检索（向量+BM25 → LLM 回答，带原文引用）      │
│  ├─ 方法引擎（9 个 Prompt 模板）：                        │
│  │   检视报告 / I·A1·A2 便签 / 三遍模式 / 读书档案 /     │
│  │   闪卡生成 / 跨书关联 / 概念展开 / 关键词定位          │
│  └─ 复习调度器（FSRS 间隔重复算法）                       │
└─────────────────────────────────────────────────────────┘
         │ 后续
┌────────▼────────────────────────────────────────────────┐
│  桌面打包：Tauri 2（复用 Web 前端 + 本地数据迁移）        │
└──────────────────────────────────────────────────────────┘
```

## 5. 技术选型（已确认）

| 层面 | 选型 |
|------|------|
| 框架 | Next.js + TypeScript（App Router） |
| 渲染 | foliate-js（EPUB 渲染） |
| 存储 | SQLite（better-sqlite3）本地优先 |
| AI | LangChain.js 生态 + 多模型（OpenAI/Claude/DeepSeek/Ollama） |

| 复习 | FSRS 间隔重复算法，可导出 Anki |
| 桌面（后置） | Tauri 2 |

| 阶段 | 内容 | 方法覆盖 | 预估 |
|------|------|---------|------|

## 7. 风险与对策

| 风险 | 对策 |
|------|------|
| 9 种方法一次做 → 范围膨胀 | 分批实现（M1→M3），每批独立可交付；方法以"Prompt 模板"实现，成本低 |
| PDF 解析成本高 | MVP 主 EPUB，PDF 用在线解析 API（MinerU）渐进支持 |
| 本地向量库体积大 | 默认在线 embedding API，本地（ollama/bge-m3）可配置 |
| 方法论功能可能"重引导、轻使用" | 全部做成"可选工具"（AI 生成后可编辑、可忽略），不做强制流程 |
| LangChain.js 依赖重 | 只使用核心模块（retriever/chain/prompt），避免引入全套 |

## 8. 设计原则

- **本地优先**：书籍、标注、便签数据默认存本地，隐私优先
- **方法可选**：所有方法论功能都是可选工具，不强制流程
- **AI 可编辑**：AI 生成内容（便签/档案/闪卡）用户均可编辑修正
- **渐进实现**：M1→M4 每批独立可交付、可验证
